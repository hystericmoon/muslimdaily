# haho design system

The visual language of haho apps, first built for Adwam and extracted so other apps (Smol next)
share it. This file is the rulebook for **app screens**. Home-screen widgets have their own rules
in each app.

Code lives in `design/src/main/java/id/haho/design/`. Token values here are the source of truth
for designers; the Kotlin files are the source of truth for code. Generated colour values and
their contrast report are in `docs/design-tokens.md`.

## Principles

1. **Calm glass.** Content sits on frosted, translucent surfaces over a soft, static aurora. Depth
   comes from translucency and a top-lit rim, never from shadows.
2. **Colour is a role, not a decoration.** Every colour comes from a Material 3 role or a glass
   role. No hex values in screens.
3. **Readable first.** Every text pairing meets WCAG 2.2 AA (4.5:1) against the worst point of
   the backdrop, in every palette, light and dark, glass on and off. A test enforces it.
4. **Quiet motion.** Short, springy, no bounce except one deliberate tap. Everything snaps when
   the system "remove animations" setting is on.
5. **One accent.** A palette (or an app's own seed) sets the accent; everything else follows from
   it. Surfaces stay near-neutral.
6. **Glass is optional.** "Glass off" turns every glass role into an opaque colour. Screens must
   look complete both ways.

## Theme entry point

```kotlin
HahoTheme(
    palette = HahoPalette.TEAL,      // one of eight; ignored when seedColor is set
    themeMode = ThemeMode.SYSTEM,    // SYSTEM, LIGHT, DARK
    glass = true,                    // false: every glass role opaque
    seedColor = null,                // an app's own accent: full scheme generated from it
    dynamicColor = false,            // wallpaper colours on Android 12+, when no seed
    greySurfaces = false,            // pure-grey surfaces; only the accent takes colour
    readingScale = 1f,               // in-app reading-size setting (HahoTheme.reading)
) { GlassBackdrop { /* screens */ } }
```

`GlassBackdrop` replaces the root `Surface`: put it once at the root (or per screen) and keep
everything above it transparent.

## Colour roles

All Material 3 roles exist and are generated from a seed with Material Color Utilities (tonal
spot; the neutral variant for grey seeds), with two overrides:

- **Surfaces** are a near-neutral tinted faintly toward the seed's hue (chroma 4; tone 98 light,
  7 dark). Teal keeps the original parchment `#FBF8F1` / soft dark `#121412`. Container steps
  (`surfaceContainerLowest` … `Highest`) come from a low-chroma palette on the surface's hue.
- **greySurfaces** sets that chroma to 0: surfaces, containers, outlines and `onSurfaceVariant`
  are pure grey and only primary/secondary/tertiary carry colour.

Use roles by meaning:

| Role | Use |
|---|---|
| `onSurface` | Body text, titles |
| `onSurfaceVariant` | Secondary text, icons in rows, captions |
| `primary` | Section headers, text buttons, links, outlined-button text, selected indicators |
| `onPrimary` on `primary` | Filled (primary glass) buttons. Near-black on the dark-theme accent, white in light. Never hard-code white. |
| `secondaryContainer` / `onSecondaryContainer` | Tinted hero cards, selected segments, tonal buttons |
| `tertiaryContainer` / `onTertiaryContainer` | Secondary badges and notes |
| `errorContainer` / `onErrorContainer` | Warnings and alerts (always with an icon or words) |
| `outline` | Component boundaries (3:1 against the surface) |
| `outlineVariant` | Dividers only |
| `HahoTheme.status.success` / `.warning` | Success and warning text and icons (no Material role); danger is `error`. Always with words or an icon |

## Glass

Glass roles are derived from the colour scheme (`glassColors(scheme, dark, enabled)`), so they
follow any palette, seed or dynamic colour. Read them with `Glass.colors`.

| Role | Light (glass on) | Dark (glass on) | Glass off | Use |
|---|---|---|---|---|
| `base` | `surface` | `surface` | `surface` | Backdrop colour |
| `glows` | primaryContainer 55%, tertiaryContainer 60%, gold 16% | 28%, 26%, 6% | none | Three radial glows: top-left, right at 62%, bottom-left |
| `card` | white 58% | white 7% | `surfaceContainerLow` | Cards, grouped lists |
| `chrome` | white 62% | white 8% | `surfaceContainer` | Top bar when scrolled, nav bar, docked bars |
| `sheet` | `surfaceContainerLow` 92% | same | `surfaceContainerLow` | Bottom sheets, dialogs |
| `tinted` / `onTinted` | `secondaryContainer` 72% | 62% | opaque | One hero card per screen, selected segments |
| `alert` / `onAlert` | `errorContainer` | 55% wash | opaque | Warnings |
| `primary` / `onPrimary` | `primary` 90% | 88% | opaque | Primary buttons, FAB |
| `tonal` / `onTonal` | `secondaryContainer` 70% | 66% | opaque | Secondary buttons |
| `clear` | white 34% | white 5% | transparent | Outlined buttons |
| `rimTop` → `rimBottom` | white 95% → 30% | white 24% → 5% | none | 1dp top-lit rim (vertical gradient) |
| `sheen` | white 32% | white 7% | none | Specular wash at the top of a surface, fading out by 50% height (38% on buttons) |

Rules:

- The backdrop is **static**. It never animates, scrolls with content or reacts to touch.
- Glass only ever sits on the backdrop or on another glass card. Never put glass over photos or
  busy content; use `sheet` (nearly opaque) for anything that floats over arbitrary content.
- Sheets and dialogs frost (blur 18dp) what is behind them on Android 12+
  (`Modifier.frostWhenOverlayOpen()` on the root content); older versions rely on the scrim.
- At most one `tinted` hero card per screen.
- With glass off, rims, sheen and glows disappear and every role is opaque; nothing else changes.
- New glass alphas must pass `GlassContrastTest` in every palette before they ship.

## Typography

Plus Jakarta Sans (variable, 400–700, SIL OFL 1.1; licence in `licenses/`). The M3 type scale
keeps its sizes and line heights; headlines, titles and labels are SemiBold.

| Style | Size / line | Weight | Use |
|---|---|---|---|
| displayLarge / Medium / Small | 57/64, 45/52, 36/44 | Regular | Big numbers, hero values |
| headlineLarge / Medium / Small | 32/40, 28/36, 24/32 | SemiBold | Screen heroes |
| titleLarge | 22/28 | SemiBold | Top bar title, empty-state title |
| titleMedium / Small | 16/24, 14/20 | SemiBold | Card titles; section headers (titleSmall in `primary`) |
| bodyLarge / Medium / Small | 16/24, 14/20, 12/16 | Regular | Row titles; summaries; notes |
| labelLarge / Medium / Small | 14/20, 12/16, 11/16 | SemiBold | Buttons; badges and chips; captions |

- `HahoTheme.reading` is the same scale multiplied by `readingScale`, for long-form text the user
  can resize in-app. UI chrome keeps the base scale.
- Pass `typography = hahoTypography(MyFamily)` to swap the face but keep the scale.
- Use tabular figures (`fontFeatureSettings = "tnum"`) for counts, sizes and timers.

## Spacing and sizes

`HahoTheme.spacing`: `xxs 2`, `xs 4`, `sm 8`, `md 12`, `lg 16`, `xl 24`, `xxl 32`, `xxxl 48` (dp).

`HahoTheme.dimens`: `screenGutter 16`, `cardPadding 20`, `minTouchTarget 48`,
`largeTouchTarget 64`, `icon 24`, `smallIcon 18`, `divider 1`, `maxContentWidth 640`.

- Screen content has a 16dp side gutter; cards pad 20dp inside.
- Lists: section header 24dp above, 8dp below; rows 56dp (one line) / 72dp (two lines) minimum.
- On tablets content is centred and capped at 640dp (`HahoScreen` does this).

## Motion

`HahoTheme.motion` (snaps everything when animations are off):

| Spec | Value | Use |
|---|---|---|
| `press()` | spring, damping 0.6 | Press scale (97% buttons, 98.5% cards) |
| `fade()` | 220ms, fast-out-slow-in | Colour and opacity |
| `layout()` | spring, no bounce, medium-low | Size changes, list placement, chevrons |
| `enter(i)` | 320ms ease-out-cubic, 40ms stagger (max 8) | First appearance, fade + 16dp lift, once per screen |
| `cardAdvance()` | spring, no bounce | Moving to the next card/page |
| `countTap()` | spring, medium bounce | The one deliberate bounce (a counter step) |

Modifiers: `pressScale`, `enterReveal(index)`, `popOn(trigger)`, `chevronRotation(expanded)`.

## Accessibility (WCAG 2.2 AA, non-negotiable)

- Text 4.5:1 and non-text 3:1 against the worst point of the backdrop. `GlassContrastTest` and
  `PaletteContrastTest` check every palette, light and dark, glass on and off, grey surfaces and a
  spread of custom seeds. Add a seed to `SampleSeeds` when an app adopts one.
- Touch targets at least 48dp; whole rows are the target for toggles, radios and checkboxes.
- State never by colour alone: selection adds a check or radio, warnings add an icon or words,
  badges are always text.
- Layouts hold at 200% font scale. At 150% and above (`isLargeFontScale()`), steppers stack and
  segmented choices become a radio list. Button and chip labels wrap; never truncate them.
- TalkBack: icon-only buttons have descriptions, decorative icons have none, headers are
  headings, live values (steppers, counters, progress) are polite live regions, segments read
  "title: option" once, checkbox rows name both states.
- Every drag has a non-drag alternative (buttons or accessibility actions).
- Reduced motion: all specs snap when the system animation scale is 0.

## Do and don't

| Do | Don't |
|---|---|
| Put `GlassBackdrop` at the root and keep scaffolds transparent | Paint opaque `Surface`s over the backdrop |
| Use `Glass.colors` and `MaterialTheme.colorScheme` roles | Hard-code hex colours or white text on the accent |
| Use one tinted hero card per screen | Tint every card |
| Use surface steps and translucency for depth | Use shadows or elevation |
| Pair success/warning/error colour with an icon or words | Signal state by colour alone |
| Check new glass alphas with `GlassContrastTest` | Raise translucency "because it looks nicer" without the test |
| Keep the backdrop still | Animate the aurora or parallax it |
| Let labels wrap at large font scales | Set `maxLines = 1` on buttons or chips |
| Keep motion under ~250ms for micro-interactions | Add bounces beyond the one deliberate tap |
